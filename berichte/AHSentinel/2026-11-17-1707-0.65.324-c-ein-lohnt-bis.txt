==== Umsetzung ====
- EINE Regel für beide Prüfungen: MK:LimitCompare(id, quellen, besterWeg): jede Entzauber-Anzeige = Entzauber-Grenze (kern); die API
  (Weg offen) = der EINE Wert über alle Wege (K:LohntBis); ohne K-Wert = Entzauber-Grenze. S28 (LimitMismatch, auch die Prüfung im
  Markt-Bericht) und K:LohntCheck nutzen sie; LohntCheck fragt bei Items ohne Entzauber-Grenze (bester Weg AH/Händler) die API direkt.
  Die Meldung nennt jetzt den besten Weg ("Lohnt bis 5640 (bester Weg haendler 6666) · abweichend: …").
- Keine angezeigte Zahl ändert sich; Tooltip unverändert (TT-STOP). Warum nicht alle Anzeigen auf den besten Weg: eine Entzauber-Anzeige
  (z. B. Sniper-Entzauberziel) mit 6666 statt 5640 würde zum Kauf über dem Entzauber-Wert führen – die Grenze gehört zum Weg.
  Falls der Supervisor/Nutzer trotzdem "alle Anzeigen = bester Weg" will: bitte entscheiden (Tooltip wäre wegen TT-STOP ausgenommen).
- S28 läuft in Portionen (je Bild 2 Items mit Entzauber-Grenze, WAIT): Nachbau Teil server 90 -> 14 ms längster Schritt.
- T696 angepasst: je Weg gleich (Entzauber 800, API 950 = AH) -> 0; Entzauber-Anzeige 790 bzw. API 900 -> beide erkannt.
