ANWEISUNG GUILDSENTINEL: GILDENBANK-BESTAND AN DISCORD
=====================================================
Stand: 3. November 2026, 19:20 · von der Prüf-Sitzung · Wunsch des Nutzers
Gehört zu: auftraege/RaidMaster/anweisung-raidmaster-gildenbank-guildsentinel.txt (Uploader und Bot, RaidMaster-Projekt)

ZIEL
GuildSentinel liest auf dem Bank-Charakter der Gilde den Bestand aus. Der RaidMaster-Uploader auf dem PC des Nutzers
(gleicher Ordner, gleiche uploader_config.json, KEINE neue .json) schickt ihn mit an den Bot, und der Bot zeigt ihn in
#gildenbank (Kategorie 🏦 GILDENBANK, unter den Regeln) und bei /bank <Suche>.
Es gibt nur noch den Kanal #gildenbank (Regeln oben, Bestand darunter), siehe auftraege/RaidMaster/anweisung-raidmaster-gildenbank-ein-kanal.txt.

Richtung: nur GuildSentinel -> Discord. Nichts kommt aus Discord zurück ins Spiel.

1. DATENFORMAT – GENAU WIE RAIDMASTER (Pflicht)
   In GuildSentinelDB.bank, gleiches Format wie RaidMasterDB.bank (RaidMaster/Bank.lua Zeile 8-9), damit der Bot denselben
   Leser (raidmaster_data.guild_bank) benutzen kann:
     GuildSentinelDB.bank = { c = Name des Bank-Charakters, t = time() beim Lesen, g = GetMoney() in Kupfer,
                              gb = Gold der Gildenbank in Kupfer oder nil, src = "bank"/"mail"/"guild",
                              i = { [Item-ID] = { n = Name, q = Qualität, c = Gesamtanzahl, ic = Symbol-ID,
                                                  w = { bag = x, bank = y, mail = z, guild = w } } } }
   - Schlüssel und Bedeutung exakt so, keine weiteren Ebenen. Zusätzliche Felder nur auf oberster Ebene und nur, wenn
     der Bot sie ignorieren kann.
   - Item-ID als Zahl-Schlüssel, Name aus GetItemInfo, sonst aus dem Link ("[Name]").

2. WANN LESEN
   - Nur auf dem Bank-Charakter: neue Option "Bank-Charakter (Bestand an Discord)" in den Optionen, ab Werk AUS, pro
     Charakter. Ohne Häkchen liest GuildSentinel nichts und schreibt kein .bank.
   - Beim Öffnen von Bank (BANKFRAME_OPENED), Briefkasten (MAIL_SHOW / MAIL_INBOX_UPDATE) und – falls der Client sie hat –
     Gildenbank (GUILDBANKFRAME_OPENED, Fächer über GetGuildBankItemLink / GetGuildBankItemInfo). Teile, die gerade nicht
     gelesen werden, aus dem letzten Stand übernehmen (wie RaidMaster Start(keep)).
   - Behälter über C_Container mit Rückfall auf die alten Funktionen (Era/TBC nie brechen). Alle Aufrufe über ns.API,
     damit die Testroutine sie simulieren kann.
   - Nie im Kampf lesen (ns.WhenOutOfCombat), Lesen in Scheiben, keine Ruckler. Geheime Werte (issecretvalue) prüfen.
   - Nach dem Lesen eine Chatzeile: "Gildenbank-Bestand gelesen: N verschiedene Items. Er kommt mit dem nächsten Upload
     in den Discord." – in allen Locale-Dateien.

3. RAIDMASTER UND GUILDSENTINEL ZUSAMMEN
   Ist RaidMaster auf demselben Charakter auch Bank-Charakter, lesen beide. Das ist erlaubt: Der Bot nimmt den Stand mit
   dem neueren t. GuildSentinel muss RaidMaster dafür nicht erkennen.

4. TESTROUTINE
   Neue Fälle im passenden Bereich (Nummern fortlaufend):
   - Bank-Charakter aus -> nichts gelesen, kein .bank
   - Bank simuliert (über ns.API) -> .bank hat das Format aus Punkt 1, Summen stimmen (c = Summe aller w)
   - nur Post gelesen -> Bankteil aus dem alten Stand bleibt erhalten
   - im Kampf geöffnet -> erst nach dem Kampf gelesen
   - Era-Client ohne C_Container -> alte Funktionen, kein Fehler
   - IM CLIENT PRÜFEN: Bank und Briefkasten auf dem Bank-Charakter öffnen, /reload, Bestand erscheint in
     #gildenbank (sobald Uploader und Bot aus dem RaidMaster-Auftrag fertig sind)

5. ABLAUF
   Mit der nächsten Version (0.9.11), zusammen mit den Punkten aus offen-guildsentinel.txt. Wie immer: komplette Dateien,
   alte Clients nie brechen, alle Locale-Dateien, CHANGELOG EN/DE, Tests unter test/ laufen lassen, vor dem Push
   python3 addon-check/addon_check.py download/GuildSentinel-<Version>.zip -> kein FEHLER.
   GuildSentinel ist auf CurseForge: Die Option ist ab Werk aus, Gilden ohne RaidMaster-Bot merken nichts davon.

Ist etwas daran falsch oder nicht machbar, bitte dem Nutzer begründet zurückmelden.
